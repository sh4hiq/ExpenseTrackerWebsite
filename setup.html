Setup guide

Install ExpenseTracker on Windows 11, connect Gmail read-only, load the local model and run your first sync. All commands run in PowerShell from the repository root.

Prerequisites

  • Windows 11 with PowerShell.
  • Node.js 24 LTS and npm 11. Check with node --version.
  • LM Studio with its local server enabled. It listens on http://127.0.0.1:1234.
  • A GPU with about 3 GB of free VRAM for the default model.
  • A Google account that receives your isybank payment notifications.

Install

npm ci
copy .env.example .env     # then edit only the values you need
npm run check              # format, lint, typecheck, tests, build

Local model

The default model for both extraction and category suggestions is mistralai/ministral-3-3b: about 2.15 GB on disk and 2.8 GB of VRAM.

lms get mistralai/ministral-3-3b
lms load mistralai/ministral-3-3b --context-length 4096 --gpu max
lms ls                      # the model must be listed
npm run worker -- health    # checks LM Studio and the model ID

You can also start LM Studio and load the model from the app: open Stato e impostazioni and choose Avvia LM Studio e carica il modello. If the lms command lives somewhere unusual, set ET_LMS_PATH.

Gmail access

You do this once. ExpenseTracker uses your own Google Cloud project, so no one else ever holds a token for your mailbox.

  1. In the Google Cloud console, create a project and enable the Gmail API.
  2. Under Google Auth platform → Branding, enter an app name and support email. Under Audience, choose External and add your Gmail address as a test user.
  3. Under Clients, create a client with application type Desktop app and download the JSON file.
  4. Save it as secrets\credentials.json. This folder is Git-ignored.
  5. Run npm run worker -- auth, open the printed address and approve read-only access. The token is saved to secrets\token.json.

You can also connect from the app with Collega Gmail in Stato e impostazioni.

While the consent screen is in Testing, Google expires the token after 7 days and syncs will report a gmail_auth error. Set the publishing status to In production to avoid weekly re-authorization. The app can stay unverified for personal use.

First run

npm run worker -- sync --dry-run   # shows what would be processed, writes nothing
npm run worker -- sync             # first run looks back 90 days
npm run worker -- status
npm run build; npm run api         # open http://127.0.0.1:4318

Scheduled sync

Run a few manual syncs first and check that status looks right. Then register an hourly task for your user only:

schtasks /Create /TN "ExpenseTracker sync" /SC HOURLY /RL LIMITED /F `
  /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"$PWD\scripts\scheduled-sync.ps1\""
schtasks /Run /TN "ExpenseTracker sync"      # test it once
Get-Content .\logs\scheduled-sync.log -Tail 5

Commands

CommandWhat it does
worker -- sync [--dry-run] [--since YYYY-MM-DD]Fetch and process new notifications. --since re-reads an older range; duplicates are ignored.
worker -- reprocess [--status …] [--limit N]Re-run extraction on stored messages without contacting Gmail.
worker -- statusMessage counts by status and the latest runs.
worker -- healthChecks configuration, database, Gmail files, LM Studio and the model.
worker -- backupOnline, integrity-checked backup to data\backups.
worker -- restore <file> --yesRestore a backup. Stop the API first.
apiLocal API and the built interface on 127.0.0.1:4318.

Prefix each with npm run.

Settings

Everything lives in .env and is validated at startup. The ones you're most likely to change:

SettingDefaultPurpose
ET_GMAIL_QUERYfrom:comunicazioni@isybank.comWhich messages are listed.
ET_GMAIL_ALLOWED_SENDERScomunicazioni@isybank.comMail from anyone else is never treated as an expense.
ET_GMAIL_INITIAL_LOOKBACK_DAYS90How far back the first sync reads.
ET_EXTRACTION_MODELmistralai/ministral-3-3bMust match lms ls exactly.
ET_EXTRACTION_TEMPLATEStrueRead known bank sentences without the model.
ET_CATEGORY_AUTO_ACCEPToffWhether model categories skip review.
ET_API_PORT4318Port for the local app. The host is always loopback.

Demo mode

To explore the interface before connecting Gmail, seed a separate database with synthetic data:

npm run demo:seed -w @et/worker
npm run demo                       # uses data\demo.db
