Your bank already emails you every payment. Now they add up.

ExpenseTracker reads your bank's payment notifications from Gmail, pulls out the amount, currency and merchant with an AI model that runs on your own PC, and files each one in a private ledger you can search, review and export.

  • No cloud AI, no telemetry
  • Data stays in SQLite on your PC

From inbox to ledger, in six careful steps

A batch worker runs on a schedule you choose. Every step is deterministic except one, and that one is checked twice before anything is saved.

  1. Find the right emails

    Lists only messages matching your bank's sender, from the last sync onwards with a 48-hour overlap. Messages already handled are skipped without being downloaded again.

  2. Clean them up

    Decodes MIME and charsets, turns HTML into plain text, cuts the footer at the bank's signature and drops mail from any sender that isn't on your allow-list.

  3. Sort by subject

    Card payments, direct debits, transfers and cash withdrawals go on. Credits, failed transfers, card creation and bank documents are set aside, keeping only metadata.

  4. Read the amount and merchant

    Known bank sentences are read by exact templates. Anything new goes to a small local model through LM Studio, constrained to a JSON schema. Date and time always come from the email header.

  5. Check every value

    The amount, currency and merchant must appear in the original text. Card numbers and account references are rejected. Anything ambiguous waits in your review queue instead of being guessed.

  6. Categorize and save

    Your merchant rules win, then built-in rules, then a model suggestion you confirm. Each record is written in one atomic SQLite transaction, so a crash never leaves half an expense behind.

Your bank emails never leave your PC

ExpenseTracker talks to exactly three things. Two of them are on your own machine.

  • Read-only, and only your bank's mail

    The Gmail scope is gmail.readonly. Only messages from your bank's sender are listed. The History API is deliberately not used, because it would expose unrelated mail.

  • AI that runs on your graphics card

    Extraction and category suggestions use a 3B-parameter model in LM Studio, about 2 GB on disk. Bank text is never sent to a hosted model.

  • A locked-down local API

    Host and Origin allow-lists stop DNS rebinding and cross-site requests. There is no generic SQL, file or shell endpoint, and the UI loads nothing from third parties.

  • Only what's needed is kept

    Logs are redacted and never contain email bodies. Excluded messages keep metadata only. Secrets, databases, backups and exports are all Git-ignored.

Honest about what the model can do

Small local models make mistakes. ExpenseTracker is designed so that a mistake becomes a question in your review queue, never a wrong number in your ledger.

Everything around the ledger

Export to CSV, Excel and PDF

Export exactly what your filters show. Spreadsheet formulas are neutralized against CSV injection, and Excel cells are written with real types.

Hourly sync with Task Scheduler

A ready PowerShell script registers an hourly task for your user only. A failed run never moves the sync cursor, so nothing is skipped.

Backups you can trust

Online, integrity-checked SQLite backups with one command, and a matching restore. Duplicate emails are impossible: each Gmail message is stored once.

Retries and reprocessing

Per-message failures retry within a budget. Re-run extraction on stored messages after changing the model or prompt, without contacting Gmail.

Configured, not coded

Swap the model, prompt, sync window or sender in .env. Every setting is validated at startup, and errors name the setting, never its value.

Try it without Gmail

A demo mode seeds a separate database with synthetic transactions, so you can explore the interface before connecting anything.

Get it running on your PC

You need Windows 11, Node.js 24, LM Studio and a Google account that receives your bank's notifications. The setup guide walks through the Google Cloud console step by step.

Open the setup guide 
> npm ci
> copy .env.example .env
> lms get mistralai/ministral-3-3b
> npm run worker -- auth        # once
> npm run worker -- sync --dry-run
> npm run worker -- sync
> npm run build; npm run api   # 127.0.0.1:4318
